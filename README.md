# 工业零件视觉抓取质检系统

> **在线体验（点开即用）**：https://hh200606.github.io/part-inspection/
> 上传一张工业零件图片，浏览器本地完成识别、抓取点定位与逐件 OK/NG 质检，图片不上传服务器。

一个面向工业零件工位的可视化质检工具：上传图片 → 识别/定位每个零件（抓取点）→ **逐件判定 OK / NG 并给出原因** → 输出可导出报告。支持**精准分类**、**标准样品模板比对**、**自动引擎切换决策链**和**数量/缺件检查**。

## 核心流程（双引擎 + 双重质检）

```
上传工业零件图片
      ↓
引擎① YOLO11n（工业零件专用模型，15 类）浏览器本地推理
      ↓ 无检出 / 域外误检（自动切换）
引擎② 视觉分割（背景差分 + 连通域）定位任意形状零件
      ↓
逐件判定：
  · 精准分类：选定目标类别，类别不符 → NG
  · 质量分：置信度 < 合格线 → NG
  · 模板比对（可选）：与标准 OK 样品相似度 < 模板线 → NG
  · 数量检查（可选）：期望数量不符 → 整批 NG
      ↓
可视化：抓取十字 + OK/NG 框 + 原因明细表 + 决策链 → 导出 JSON 报告
```

### 引擎选择（左侧面板）

- **自动（默认）**：YOLO 优先。YOLO 无检出，或只检出纸箱/玻璃/亚克力等域外误检类时，**真正切换**到视觉分割；画面下方会显示 `YOLO11n 检出 N 件 → 无检出 → 自动切换 → 视觉分割检出 M 件 → 最终引擎` 的决策链，右上角芯片同步显示本次实际使用的引擎。
- **仅 YOLO 精准分类**：识别 15 类已知零件；可指定目标类别，只统计该类，类别不符直接 NG。
- **仅视觉分割**：背景差分 + 连通域定位任意形状零件，再用内置样图库比对出具体类别（见下节），适合 3D 渲染 / 规则背景 / 密集合集图。

### 为什么需要双引擎

YOLO11n 只对**真实拍摄**的 15 类零件（螺丝、螺母、PCB、电机等）有效。对于 3D 渲染图 / CAD 零件合集 / 密集小零件，YOLO 置信度往往极低，甚至会自信地把渲染螺丝认成「纸箱」——这是模型训练域的限制，不是程序故障。此时视觉分割引擎（不依赖模型）通过背景差分 + 连通域分析，能定位任意形状、任意类别的零件并给出抓取点。

## 质检规则（逐件 OK / NG）

每个零件单独判定，明细表与导出报告中都有 `verdict` 和 `reasons`：

| 规则 | 判定 |
|---|---|
| 指定目标类别且识别类别不符（或未识别类别） | NG |
| 置信度 / 质量分 < 合格判定线 | NG |
| 设置了标准样品且相似度 < 模板相似度合格线 | NG |
| 以上全部满足 | OK |
| 期望零件数量 > 0 且检出数量不符 | 整批 NG · 数量不符（仍保留逐件明细） |

总结果取最差项：**未检出 / NG · 数量不符 / NG · N 件不合格 / OK · 合格**。
质量分来源：YOLO 模式为检测置信度；视觉分割模式为形状填充率换算的分数（0.35~0.99）。

## 标准样品模板比对（可选）

1. 在左侧「标准 OK 样品」上传一张只含**一个合格零件**的图片（纯色背景更好）。
2. 系统自动用分割结果裁剪主体；若无分割结果则用整图作为模板。
3. 提取 64×64 颜色分布（35%）、结构灰度（45%）、长宽比（20%）三类特征。
4. 检测时对每个零件裁剪同一区域并比对，相似度低于「模板相似度合格线」（默认 0.75）判 NG。
5. NG 时会**指出具体缺陷**：把相似度拆成颜色（35%）、结构纹理（45%）、长宽比例（20%）三项，自动挑出拖低总分最多的那项，例如
   `与标准样品相似度 58% < 75%（表面纹理/结构不符：颜色97% / 结构53% / 比例0%）`。
   结果区、明细表、CSV 和报告中都会显示原因；导出的 JSON 含 `template_detail` 分项数据。

> 模板比对适合**同款产品的一致性检查**：是否缺特征、颜色/尺寸明显偏差。它不是毫米级缺陷检测；划痕、裂纹需要专门的缺陷检测模型。

## 视觉分割也能识别类别

视觉分割原本只做定位（输出「零件1/零件2」）。现在内置了一张 71 KB 的类别参考图 `test-images/class-refs.png`（15 类样图拼图），对每个分割框先收紧到零件本体、再提特征与 15 类比对，输出**具体类别 + 相似度**（如「电路板 · 类别相似 96%」）；相似度低于 62% 标为「未知零件」并以橙色框提示。实测 15 类样图紧裁剪比对 15/15 正确。

**选中目标类别**后，三模式统一只统计并定位该类零件：决策链显示「按目标类别定位：螺丝 1/1 件」，未检出时明确提示「未检出目标类别『螺母/螺栓』」，便于快速筛选某一类零件。

## 导出报告

检测完成后右侧有三个导出按钮：

- **表格 (CSV)**：Excel / WPS 直接打开，含质检结论、说明、引擎、数量、OK/NG 明细与原因（UTF-8 BOM，中文不乱码）。
- **报告 (可打印)**：排版好的 HTML，浏览器打开后 Ctrl+P 可打印或另存为 PDF，含总判定、KPI、逐件明细与失败原因。
- **原始数据 (JSON)**：完整结构化数据，含 `verdict` / `reasons` / `class_similarity` / `template_detail` / 归一化抓取点坐标。

## 使用方法

1. 打开页面（本地服务或公网链接）
2. 点击/拖拽上传工业零件图片（JPG / PNG / WEBP）
3. 调整参数：
   - **检测引擎**：自动 / 仅 YOLO / 仅视觉分割
   - **目标零件类别**：可选，选定后只认这一类，用于精准分类
   - **置信度阈值**：低于此值的目标不纳入统计
   - **合格判定线**：置信度 ≥ 此值才可能判 OK
   - **视觉分割灵敏度 / 最小零件面积**：分割引擎参数
   - **标准 OK 样品 + 模板相似度合格线**：可选，同款产品一致性比对
   - **期望零件数量**：可选，设置后数量不符直接 NG
4. 点击「开始检测与质检」
5. 查看画面上的 OK(绿)/NG(红)/未知(橙) 框、决策链、逐件原因明细，可导出 CSV 表格、可打印报告或 JSON 原始数据

## 可识别零件（15 类）

螺丝、螺母/螺栓、PCB 电路板、电机、电池、工具、线缆、金属型材、亚克力板、3D 打印件、塑料容器、纸箱、玻璃件、线轴、木料

> 这是创客/工业场景的零件检测模型，对螺丝和 PCB 精度较高。若你的零件不在上述类别中，模型不会识别——这是模型能力边界，不是 bug。

## 自动模式的保护机制

1. **最小面积随图片尺寸缩放**：以 640×640 为基准，小图上零件像素少时阈值按比例缩小。
2. **0 检出自检重试**：按当前参数一个零件都没检出时，自动逐级放宽分割阈值与面积下限重试 2 档，并在决策链中提示。
3. **粘连/渐变背景保护**：只有「多个大块合计 > 20% 画面」或「单块几乎占满整图」时才判为背景未分离并拒绝输出；单个占比大的特写零件（如电池近照）不会被误杀。
4. **域外误检保护**：YOLO 只在检出 ≥2 个工业强类且过合格线，或 ≥1 个强类置信度 ≥0.85 时被采信；否则自动切换视觉分割。指定目标类别时，YOLO 检出该类即采信。

## 什么样的图片能检出（重要）

| 模式 | 适用图片 | 不适用 |
|---|---|---|
| 仅 YOLO 模型识别 | **真实拍摄**的螺丝、螺母/螺栓、PCB、电机、电池、工具、线缆等 15 类零件；背景干净、光照正常、零件不过小 | 3D 渲染 / CAD 截图 / 零件合集 / 不在 15 类内的物体 |
| 仅视觉分割定位 | **背景与零件明暗差异明显**的图片：纯色/渐变背景、规则排布、3D 渲染、密集小零件 | 背景杂乱、零件与背景同色、零件互相粘连成一片 |
| 自动（默认） | 先跑 YOLO，不可信时切换视觉分割；覆盖以上两类 | 同上两者的共同限制 |

要点：零件与背景要有明暗/颜色反差；零件彼此不要粘连；单个零件别太小（建议 ≥ 40×40 像素）。渐变背景、强阴影、带水印的电商渲染图两套引擎都可能失败，请换用纯色均匀背景、无水印、零件彼此分离的实拍图。

## 技术说明

- 纯前端：ONNX Runtime Web（WASM）在浏览器本地推理，图片不上传服务器
- 模型：`models/yolo11n_makerspace.onnx`（10 MB，opset17，输入 640×640，输出 `[1,19,8400]`）
- 预处理：letterbox + RGB→CHW（正确处理 RGBA 四通道）
- 后处理：逐类 NMS，坐标还原到原图
- 模板比对：Canvas 读取像素，归一化颜色直方图 + 结构灰度 + 长宽比加权，无第三方依赖
- 模型来源：huggingface.co/pavanyadava07/makerspace-yolo11n（CC BY-NC-SA 4.0，非商用）

## 本地运行

```bash
cd part-inspection
python -m http.server 8002
# 浏览器打开 http://localhost:8002
```

> 必须通过 HTTP 服务访问，不能用 `file://` 直接打开（浏览器安全策略禁止读取本地 ONNX 模型）。首次加载需联网从 CDN 获取 ONNX Runtime Web 脚本。在线版已部署在 GitHub Pages，无需本地服务。
